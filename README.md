# GIJO_BridgeAI

> 노트북에서 원격 GPU 서버에 SSH 로 붙어 GPU 상태를 보고, AI 요청을 **SSH 터널**로 그 서버에 넘기는 연결 도구

메모리가 부족한 노트북이나 일반 PC 에서, 집이나 사무실에 둔 GPU 서버(예: NVIDIA DGX Spark · RTX 워크스테이션)로 AI 연산 요청을 넘깁니다.
편집기나 파이썬 코드의 Base URL 을 `http://127.0.0.1:3000/v1` 로 바꾸기만 하면 됩니다.

## 설치 (Windows)

1. [Releases](https://github.com/gijotour/GIJO_BridgeAI/releases) 에서 `GIJO-BridgeAI-Setup-x.y.z.exe` 를 받아 실행합니다.
2. 설치하면 바로 「GIJO BridgeAI」 창이 열립니다. 시작 메뉴에도 생깁니다.
3. 새 판이 나오면 앱이 알아서 받아 두고, 재시작할지 묻습니다. 「도움말 → 시작할 때 업데이트 확인」에서 끌 수 있습니다.

> **설치 파일은 코드 서명이 되어 있지 않습니다.** 처음 실행할 때 Windows 가 「Windows의 PC 보호」 경고를 띄울 수 있습니다.
> 「추가 정보 → 실행」을 누르면 설치됩니다. 소스가 궁금하면 이 저장소의 코드를 보시거나 아래 「코드로 실행」대로 직접 돌릴 수 있습니다.

### 코드로 실행 (Windows · macOS · Linux)

```bash
git clone https://github.com/gijotour/GIJO_BridgeAI.git
cd GIJO_BridgeAI
npm install
npm start            # 브라우저로 http://localhost:3000 을 엽니다
npm run desktop      # 또는 설치판과 같은 창으로 엽니다
```

## 누구에게 맞나

**가장 잘 맞는 사람: GPU 서버는 집·사무실에 있는데, 일은 노트북으로 하는 개인 개발자와 소규모 팀**

- **DGX Spark(GB10) 같은 개인용 AI 기기를 산 개발자** — 큰 모델은 기기에서 돌리고, 카페·출장지의 가벼운 노트북에서는 편집기(Cursor · Continue 등)로 그 모델을 씁니다.
- **GPU 서버 한 대를 몇 명이 나눠 쓰는 소규모 개발팀·연구실** — 각자 자기 SSH 계정으로 같은 서버를 씁니다.
- **소스 코드나 고객 자료를 외부 AI 에 보낼 수 없는 회사** — 자체 서버의 모델만 쓰므로 자료가 회사 밖으로 나가지 않습니다.

맞지 않는 경우

- GPU 서버가 없다면 이 앱으로 할 수 있는 일이 없습니다(서버를 빌려주는 서비스가 아닙니다).
- 이미지·영상처럼 큰 파일을 계속 주고받는 일은 SSH 터널이 느립니다(아래 「측정」).
- 수십 명이 쓰는 조직은 사람마다 SSH 계정을 나눠 주기보다, 사내 전용 게이트웨이와 권한 관리를 두는 편이 맞습니다.

### 서버 기기별 지원 (v1.1.0)

AI 요청을 넘기는 기능은 **어떤 서버든** 됩니다(SSH 와 추론 서버만 있으면 됩니다). 기기에 따라 다른 것은 메모리·온도 표시입니다.

| 서버 기기 | 메모리·온도 표시 |
|---|---|
| NVIDIA 전용 GPU (RTX · A100 · H100 등) | 됩니다 |
| NVIDIA GB10 계열 (DGX Spark 와 같은 칩을 쓰는 기기) | 됩니다 — 「통합 메모리」로 표시 |
| NVIDIA Jetson | 같은 방식으로 될 것으로 보지만 시험하지 않았습니다 |
| AMD (Ryzen AI Max · Radeon), Mac (Apple Silicon) | 아직 「확인 불가」 — 다음 판(v1.2)에서 지원할 예정 |

## 처음 쓰는 순서

**서버 쪽 (한 번만)**

1. 서버에 SSH 접속이 되는지 확인합니다(같은 망이면 서버 주소, 밖에서는 Tailscale 같은 VPN 주소).
2. 추론 서버를 띄우고 모델을 받아 둡니다. Ollama 라면 `ollama serve`, `ollama pull qwen3:8b`.
   기본 설정 그대로 두세요. 추론 서버를 외부에 열 필요가 없습니다.

**내 PC 쪽**

1. 「GIJO BridgeAI」를 엽니다.
2. 서버 주소, 계정 ID, 비밀번호를 넣고 「SSH 접속하고 GPU 상태 읽기」를 누릅니다.
   SSH 키로 접속한다면 「SSH 키 · 추론 서버 포트」를 펼쳐 키 파일 경로를 넣고 비밀번호는 비워 둡니다.
3. 처음 접속하는 서버는 서버 지문을 기억해 둡니다. 다음부터 지문이 달라지면 접속을 막습니다.
4. 오른쪽에 GPU·메모리 상태와 **서버에 있는 모델 목록**이 나오면 연결된 것입니다.
5. 왼쪽 「로컬 프록시」 주소를 복사해 쓰는 도구의 Base URL 에 넣습니다. 모델 이름은 목록에서 「이름 복사」로 가져옵니다.

**도구별 넣는 곳**

| 도구 | 넣는 곳 |
|---|---|
| Continue (VS Code) | 모델 설정에서 `provider: openai`, `apiBase` 에 프록시 주소, `model` 에 복사한 이름 |
| Cursor | 모델 설정의 OpenAI Base URL 덮어쓰기 칸에 프록시 주소(키 칸은 아무 값) |
| 파이썬 (openai 라이브러리) | `OpenAI(base_url="프록시 주소", api_key="bridgeai")` |

> 포트 3000 을 다른 프로그램이 쓰고 있으면 앱이 3001, 3002 … 를 씁니다. 그때 프록시 주소도 바뀌니, 화면에 보이는 주소를 그대로 쓰세요.
> 도구마다 설정 화면 이름은 판에 따라 다를 수 있습니다.

**자주 막히는 곳**

| 보이는 것 | 할 일 |
|---|---|
| SSH 접속 실패 | 주소·포트·계정을 확인합니다. 밖에서라면 VPN 이 켜져 있는지 봅니다. |
| 「호스트 키가 다릅니다」 | 서버를 다시 설치한 게 아니라면 접속하지 마세요. 다시 설치했다면 「도움말 → 호스트 키 기록 폴더 열기」에서 그 서버 줄을 지웁니다. |
| 「추론 서버가 답하지 않습니다」 | 서버에서 추론 서버가 떠 있는지, 포트(Ollama 11434 · vLLM 8000 · llama.cpp 8080)가 맞는지 봅니다. |
| 모델 목록이 비어 있음 | 서버에서 모델을 먼저 받습니다(예: `ollama pull qwen3:8b`). |

## 하는 일

1. **원격 GPU 서버 SSH 연결과 자원 조회**
   - 비밀번호 또는 **SSH 키 파일**로 접속해 `nvidia-smi` 로 GPU 이름·메모리·온도를 읽고, 5초마다 다시 읽습니다.
   - **DGX Spark(GB10)처럼 GPU 와 CPU 가 메모리를 같이 쓰는 기기**는 `nvidia-smi` 가 메모리를 「Not Supported」로 냅니다
     ([NVIDIA 설명](https://docs.nvidia.com/dgx/dgx-spark/known-issues.html)). 그때는 `/proc/meminfo` 의 시스템 메모리를 「통합 메모리」로 보여 줍니다.
   - `nvidia-smi` 가 없으면 숫자를 지어내지 않고 「확인 불가」로 둡니다.

2. **SSH 터널로 AI 요청 전달**
   - `http://127.0.0.1:3000/v1` 로 보낸 요청을 **이미 연 SSH 연결 안쪽으로** 원격 서버의 `127.0.0.1:11434`(Ollama)에 넘깁니다.
   - 그래서 원격 추론 서버를 외부나 사내망에 열지 않아도 됩니다. 서버 쪽은 기본 설정(127.0.0.1 에만 열림) 그대로 두세요.
   - vLLM(보통 8000)·llama.cpp 서버(8080)를 쓰면 「SSH 키 · 추론 서버 포트」에서 포트를 바꿉니다.

3. **원격 서버에 있는 모델 목록**
   - SSH 터널로 원격 추론 서버에 물어 받아 둔 모델을 보여 줍니다(Ollama `/api/tags`, 아니면 OpenAI 호환 `/v1/models`). 이름을 복사해 편집기에서 고르면 됩니다.

4. **호스트 키 확인**
   - 처음 접속한 서버의 호스트 키 지문을 적어 두고, 다음 접속 때 키가 달라져 있으면 접속을 막습니다.
   - 설치판은 사용자 데이터 폴더(`%APPDATA%\GIJO BridgeAI\known_hosts.json`)에 적습니다. 「도움말 → 호스트 키 기록 폴더 열기」로 열 수 있습니다.

## 보안

- 로컬 서버는 **이 PC(127.0.0.1)에서만** 열립니다. 같은 와이파이의 다른 기기에서는 접속할 수 없습니다.
- 다른 웹사이트가 브라우저를 통해 이 프록시를 쓰지 못하게, 내 PC 주소(localhost)가 아닌 곳에서 온 요청은 막습니다.
- SSH 비밀번호와 키 암호는 저장하지 않습니다. 접속이 끝나면 입력칸에서도 지웁니다.
- 이 앱이 스스로 바깥과 통신하는 것은 업데이트 확인(GitHub Releases) 하나뿐이고, 끌 수 있습니다.

> 왜 터널인가: 추론 서버(Ollama 등)는 기본으로 비밀번호가 없습니다. 원격에서 쓰려고 외부에 열어 둔 Ollama 서버가
> 2026년 1월 기준 17만 대 넘게 인터넷에서 발견됐다는 보고가 있습니다([Twingate](https://www.twingate.com/blog/ollama-server-exposure)).
> SSH 터널은 서버 설정을 바꾸지 않고 새로 열리는 포트도 없습니다.

## 어떤 환경에 맞나

| 환경 | 맞는 정도 | 이유 |
|---|---|---|
| 같은 집·사무실 망의 GPU 서버 | 가장 좋음 | 지연이 작습니다. 서버는 SSH(22)만 열려 있으면 됩니다. |
| 밖에서 집·사무실 서버로 | 좋음 | 공유기 포트를 열지 말고 Tailscale·WireGuard 같은 VPN 위에서 SSH 로 붙는 것을 권합니다. |
| DGX Spark(GB10) | 좋음 | 128GB 통합 메모리라 70B 급 모델도 올라갑니다. 메모리는 「통합 메모리」로 표시됩니다. |
| 채팅·코딩 도우미(LLM) | 잘 맞음 | 주고받는 글자가 작아(요청당 수 KB) 전송보다 GPU 연산이 시간을 좌우합니다. |
| 큰 파일을 자주 주고받는 일 | 덜 맞음 | 아래 측정처럼 SSH 터널의 처리량에는 한계가 있습니다. 모델 파일은 서버에서 직접 받으세요. |

### 측정 (2026-11-24, 같은 PC 안 가짜 서버, 300회 중앙값)

| | 직접 HTTP | BridgeAI 경유(SSH 터널) |
|---|---|---|
| 작은 요청 한 번 | 0.47 ms | 1.38 ms |
| 32MB 응답 처리량 | 202 MB/s | 47 MB/s |

요청마다 약 1 ms 가 더해집니다. LLM 한 번의 응답이 보통 수 초 걸리는 것에 비하면 작습니다. 큰 응답에서는 터널이 느립니다.
실제 망에서는 망 지연이 더해지므로 같은 망 안에서 쓰는 것이 가장 빠릅니다.

### 비슷한 다른 도구

- [NVIDIA Sync](https://docs.nvidia.com/sync/latest/) — DGX Spark 용 트레이 앱. 키를 만들어 서버에 넣고, 포트 포워딩으로 서버의 웹 앱을 내 PC 에서 엽니다. BridgeAI 와 같은 방식(SSH 터널)입니다.
- [LM Studio LM Link](https://lmstudio.ai/docs/lmlink) — 다른 기기의 모델을 내 PC 의 `localhost:1234` 처럼 쓰게 합니다(Tailscale 기반). 양쪽에 LM Studio 가 있어야 합니다.
- [llama.cpp RPC](https://github.com/ggml-org/llama.cpp/tree/master/tools/rpc) — 모델 하나를 여러 기기에 나눠 올립니다. 기기끼리 주고받는 양이 많아 빠른 망이 필요합니다.

BridgeAI 는 서버에 이미 있는 Ollama·vLLM 을 그대로 두고, 노트북에는 이 앱 하나만 깔아 쓰는 쪽입니다.
